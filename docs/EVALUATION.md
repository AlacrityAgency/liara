# گزارش داوری شبیه‌سازی‌شده‌ی «سُکان» — چالش لیارا × استارکوچ

> **تاریخ:** ۱ آبان ۱۴۰۵ (2026-10-23)
> **روش:** چهار داور مستقل (عامل‌های Sonnet)، هر کدام مسئول یک ردیف از جدول بارم‌بندی. داورها کد را خواندند. بعضی از آن‌ها سرور را اجرا کردند و سناریوهای دمو را با curl و Playwright آزمودند. هیچ فایلی در مخزن تغییر نکرد.
> **وضعیت پایه:** `npm install && npm test` سبز است (۲۲ تست، ۸ مجموعه). ویدئوی دمو در مخزن نیست و داوری نشده است.

**جمع‌بندی یک‌خطی:** «سُکان» روی کاغذ (وایت‌پیپر و ماتریس API) یکی از کامل‌ترین طرح‌هاست. ولی MVP فعلی یک **دموی شبیه‌سازی‌شده روی یک اپ محلی** است. فاصله‌ی بین ادعا و پیاده‌سازی، بزرگ‌ترین ریسک داوری است.

## ۲. نقاط قوت (به تأیید هر چهار داور)

1. **مسیرها و بدنه‌های API درست‌اند.** `/v1/me`، `/v1/billing`، `/v1/projects`، `actions/restart`، `actions/scale`، `resize` و `update-envs` با `paas.yaml` رسمی می‌خوانند. `update-port` هم با CLI رسمی مطابق است.
2. **`api-matrix.md`** نگاشت دقیق و منبع‌دار (OAS در برابر CLI) از حدود ۴۰ اندپوینت ارائه می‌دهد.
3. **موتور Policy:** سطوح L0 تا L3، توکن HMAC گره‌خورده به هش پارامترها، TTL پنج‌دقیقه‌ای، nonce یک‌بارمصرف (ضد replay)، تایپ نام و پنجره‌ی لغو ۱۰ ثانیه‌ای برای L3. این‌ها **سمت سرور** اعمال می‌شوند، نه فقط در UI.
4. **پارسر لاگ چندزبانه** برای Node، Python، PHP و Go، با خوشه‌بندی امضای خطا، رگرسیون خطی برای روند نشت حافظه، استخراج محل مشکوک از stack trace و ارجاع هر فرضیه به شناسه‌ی شاهد.
5. **نگاشت خطای HTTP به پیام سه‌بخشی فارسی** (چه شد / چرا / حالا چه کنیم).
6. **رابط RTL فارسی** با کارت تأیید شش‌بخشی (چه، چرا، هزینه، اثر، بازگشت، معیار موفقیت)، تب Audit و تب سناریوهای دمو.
7. **سناریوی ۵۰۰ (نبود `DATABASE_URL`)** سر تا ته کار می‌کند: پنج رخداد خطا، اطمینان بالا، اشاره به `src/db/client.js:24` و کارت L2.

### 🟡 جزئی

- `res.json()` روی پاسخ ۲۰۰ با بدنه‌ی خالی (restart و resize) خطا می‌دهد و به اشتباه `NETWORK_ERROR` گزارش می‌شود (`client.ts:77`). timeout، retry و مدیریت rate-limit هم ندارد.
- `getLogs` پارامتر `since` را اختیاری گرفته در حالی که spec آن را الزامی می‌داند (`client.ts:169`). ماتریس API نسخه‌ی v2 را مستند کرده ولی کد v1 را صدا می‌زند.
- کلید HMAC در هر بار اجرا تصادفی است (`tokens.ts:17`)، پس تأییدها با ری‌استارت سرور از بین می‌روند. Audit فقط در حافظه است و `verify()` جز در تست‌ها صدا زده نمی‌شود.
- سه پلن محاسبه می‌شوند ولی در UI نمایش داده نمی‌شوند. کارت `options[1]` را ثابت انتخاب می‌کند. پورت ۳۰۰۰ اعلام می‌شود در حالی که اپ روی ۳۱۰۰ اجرا می‌شود. `CHAOS_*` به‌عنوان env الزامی به کاربر نشان داده می‌شود.
- `alert()` با کدهای خام (`WRONG_CONFIRMATION`). شناسه‌های خام شاهد (`ev_1`) در UI. کارت تأیید در پنل ۳۸۰ پیکسلی بریده می‌شود.
- `scenario-tamper-test` با شناسه‌ی جعلی فقط `UNKNOWN_APPROVAL` را ثابت می‌کند، نه دستکاری پارامتر.
- `knowledge/`، `scripts/notebooklm_rag.py` و `docs/RAG_*` به محصول ربطی ندارند و داور را گیج می‌کنند.
